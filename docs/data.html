About Freddie Mac

The data originates from Freddie Mac, a group created by Congress in an effort to make mortgages more accessible to Americans. This accessibility is derived from Freddie Mac’s mortgage purchases. Lenders sell mortgage loans to Freddie Mac, who in turn uses the assets as securities sold to investors. Securities give one the right to something else– a financial contract. In this case, mortgages as securities give investors a monthly stream of income for decades. As a main purchaser of mortgages, Freddie Mac has a large amount of mortgage data across the entire US. These data points are ideal for the Home Loan Adviser model.

About the Raw Data

The data is provided by Freddie Mac in zip files by year. The download is available here. A guide is also provided here. Each year of the SFLL data is composed of quarters, which are provided in zip files as well. Each quarter contains two files: one file contains loan origination data and the other contains the performance history of each loan. Their “key” is a column named loan_sequence_number to be used for joining. This key is renamed loan_id.

The Data Process

The next section follows the step by step evaluation, cleaning, and encoding of the Freddie Mac Data. The example shown uses 2018 Q1. The same logic was then placed into an automated script so the other quarters and years could be standardized into the same final format.

Data Load & Clean- Origination

#-- data load-- including NA values mentioned in dictionary
or_2018= pd.read_csv("~/projects/data/homeloanadvisor/historical_data_2018Q1.txt", sep="|", header=None, na_values=["", "9999", "999", "9", "   ", "X"], low_memory=False)

#-- column names--
or_2018.columns= ["credit_score", "first_payment_date", "first_time_buyer", "maturity_date", "msa", "mi_percent", "num_units", "occupancy", "cltv", "dti", "upb", "ltv", "or_interest_rate", "channel", "ppm", "amortization", "prop_state", "prop_type", "zipcode", "loan_id", "loan_purpose", "or_loan_term", "num_borrowers", "seller", "servicer", "super_conforming", "pre_harp_loan_id", "program_indicator", "harp_indicator", "prop_valuation", "interest_only", "mi_cancel"]

#-- date features--
first_payment= pd.to_datetime(or_2018["first_payment_date"], format="%Y%m", errors="coerce")
maturity= pd.to_datetime(or_2018["maturity_date"], format="%Y%m", errors="coerce")

or_2018["first_payment_year"]= first_payment.dt.year
or_2018["first_payment_month"]= first_payment.dt.month
or_2018["maturity_year"]= maturity.dt.year
or_2018["maturity_month"]= maturity.dt.month

For our application we will drop several variables. The HARP program helped borrowers refinance their home when their home’s value was less than their mortgage.1 The data points that identify with HARP will also be dropped because the data points represent a borrower that would not typically meet Freddie Mac’s regular qualifications. Zip code will be dropped because its high cardinality is not worth keeping. We can use msa later for a metro or non-metro flag. cltv will be dropped because it is highly similar to ltv. We’ll keep loan_id as a join key.

#-- removing HARP--
or_2018= or_2018[or_2018["harp_indicator"].isna()].copy()

#-- dropping irrelevant variables--
drop= ["pre_harp_loan_id", "amortization", "harp_indicator", "program_indicator", "seller", "servicer", "first_payment_date", "maturity_date", "zipcode", "cltv"]

or_2018= or_2018.drop(columns=drop)

Encoding

The data dictionary provided by Freddie Mac specifies what the missing values are. The msa variable, for example, has missing values that may mean a property is not in a metropolitan area, or may actually mean “unknown”. Zip code data appears in every entry, so imputation is possible using overlap. But a simpler and more reliable approach is to code a new variable using the msa column as binary: metro area or not.

#-- msa to metro area binary--
or_2018["metro_area"]= or_2018["msa"].notna().astype(int)
or_2018= or_2018.drop(columns="msa")

There are columns with low cardinality that cannot be coded as binary but are better served by one-hot encoding.

#-- categorical encoding--
categorical_cols= ["first_time_buyer", "loan_purpose", "prop_type", "occupancy", "channel", "num_units"]

or_2018[categorical_cols]= or_2018[categorical_cols].fillna("Unknown")
or_2018= pd.get_dummies(or_2018, columns=categorical_cols, drop_first=True, dtype=int)

Numerical variables such as ltv and credit_score are skewed and will be imputed using the median. The median imputation will be completed during the data build so every quarter of the Freddie Mac datasets is complete. The modeling report will not need to repeat this imputation for the same standardized files.

#-- numeric imputation--
numeric_impute= ["credit_score", "dti", "ltv", "mi_percent", "prop_valuation", "upb", "or_interest_rate"]

or_2018[numeric_impute].skew()

for col in numeric_impute:
    or_2018[col]= or_2018[col].fillna(or_2018[col].median())

Variables that are not useful for the app or standardized modeling file will be dropped. These variables are removed consistently so every quarterly dataset follows the same final set up.

#-- dropping low-value variables--
or_2018[["ppm", "super_conforming", "interest_only"]].nunique()
or_2018= or_2018.drop(columns=["ppm", "super_conforming", "interest_only"])

Data Load & Clean- Performance

#-- performance load--
perf_2018= pd.read_csv("~/projects/data/homeloanadvisor/historical_data_time_2018Q1.txt", sep="|", header=None, na_values=["", "9999", "999", "   ", "X"], low_memory=False)

For the performance file, "9" was not included in the missing value list because zero_balance_code = 9 is a real category. It represents REO disposition.

#-- performance column names--
perf_2018.columns= ["loan_id", "report_period", "current_upb", "delinquency_status", "loan_age", "remaining_months", "defect_settlement_date", "modification_flag", "zero_balance_code", "zero_balance_effective_date", "current_rate", "current_deferred_upb", "ddlpi", "mi_recoveries", "net_sales_proceeds", "non_mi_recoveries", "expenses", "legal_costs", "maintenance_costs", "taxes_insurance", "misc_expenses", "actual_loss", "modification_cost", "step_modification_flag", "deferred_payment_plan", "eltv", "zero_balance_removal_upb", "delinquent_accrued_interest", "disaster_delinquency", "borrower_assistance", "current_month_mod_cost", "interest_bearing_upb"]

Only the fields needed to construct the target variable and summarize the loan termination outcome were kept. The performance file contains repeated monthly rows for each loan, so it cannot be merged directly to the origination file without creating duplicate loan rows.

#-- keeping needed performance variables--
keeping= ["loan_id", "report_period", "delinquency_status", "zero_balance_code"]

perf_2018= perf_2018[keeping].copy()

Encoding

The categorical variables will be mapped for interpretation. zero_balance_code is mapped to a readable label, while delinquency_status is converted into the target variable.

#-- delinquency map--
delinquency_map= {
    "0": "Current or <30 Days Delinquent",
    "1": "30-59 Days Delinquent",
    "2": "60-89 Days Delinquent",
    "3": "90-119 Days Delinquent",
    "4": "120-149 Days Delinquent",
    "5": "150-179 Days Delinquent",
    "6": "180-209 Days Delinquent",
    "RA": "REO Acquisition"
}

#-- zero balance map--
zero_balance_map= {
    1.0: "Prepaid or Matured",
    2.0: "Third Party Sale",
    3.0: "Short Sale or Charge Off",
    9.0: "REO Disposition",
    15.0: "Whole Loan Sale",
    16.0: "Reperforming Loan Securitization",
    96.0: "Defect Prior to Termination"
}

perf_2018["zero_balance_label"]= perf_2018["zero_balance_code"].map(zero_balance_map).fillna("Not Applicable")

We’ll use the industry standard “90+ days delinquent”. The goal is to estimate the probability that a loan becomes 90 or more days delinquent at any point during the observed performance history.

#-- target: any 90+ days delinquent--
dq_num= pd.to_numeric(perf_2018["delinquency_status"].replace({"RA": 99}), errors="coerce")

target= (
    dq_num
    .groupby(perf_2018["loan_id"])
    .max()
    .ge(3)
    .astype(int)
    .reset_index(name="any_90_dpd")
)

The category RA is defined in the dictionary as REO acquisition. These loans will be treated as 90+ days delinquent because REO acquisition reflects a severe default or foreclosure outcome. zero_balance_code will be useful because it tells why a loan was closed or terminated, but it will not be used as a predictor variable in the final model. It is retained for app interpretation and audit use.

#-- last observed termination code per loan--
zero_bal= (
    perf_2018[perf_2018["zero_balance_code"].notna()]
    .sort_values(["loan_id", "report_period"])
    .groupby("loan_id")["zero_balance_code"]
    .last()
    .reset_index()
    .rename(columns={"zero_balance_code": "termin_code"}))

#-- joining--
target= target.merge(zero_bal, on="loan_id", how="left")

#-- fill loans with no observed termination event--
target["termin_code"]= target["termin_code"].fillna(0)

#-- final join--
final_2018= or_2018.merge(target, on="loan_id", how="inner")

#-- csv checkpoint--
final_2018.to_csv("~/projects/data/homeloanadvisor/model_input_2018Q1.csv", index=False)

State Default Rate

A borrower’s property state could help output an estimate of mortgage risk because delinquency rates can vary by location. However, if state-level default rates are calculated using the entire dataset, the feature would be considered data leakage. To avoid this, state default rates were calculated using the train split, then mapped onto the train and test data.

#-- train test split--
train_, test_= train_test_split(
    final_2018,
    test_size=0.3,
    random_state=212,
    stratify=final_2018["any_90_dpd"])

train_= train_.copy()
test_= test_.copy()

#-- state default rate on train only--
state_def_rate= (
    train_
    .groupby("prop_state")["any_90_dpd"]
    .mean()
    .reset_index(name="state_def_rate"))

#-- fallback rate for unseen states--
global_def_rate= train_["any_90_dpd"].mean()

#-- mapping train-only proportions to states--
state_lookup= dict(zip(state_def_rate["prop_state"], state_def_rate["state_def_rate"]))

train_["state_def_rate"]= train_["prop_state"].map(state_lookup)
test_["state_def_rate"]= test_["prop_state"].map(state_lookup).fillna(global_def_rate)

The prop_state variable is removed after the state-level default rate is created. loan_id is removed because its an identifier, and termin_code is removed because it represents information observed after origination.

#-- removing identifier and audit columns--
train_= train_.drop(columns=["loan_id", "prop_state", "termin_code"], errors="ignore")
test_= test_.drop(columns=["loan_id", "prop_state", "termin_code"], errors="ignore")

#-- csv checkpoint--
train_.to_csv("~/projects/data/homeloanadvisor/train2018.csv", index=False)
test_.to_csv("~/projects/data/homeloanadvisor/test2018.csv", index=False)

state_def_rate.to_csv("~/projects/data/homeloanadvisor/state_def_rate_2018Q1.csv", index=False)

Automated Setup Script

The 2018 Q1 process was converted into a Python script so the same cleaning logic could be applied to every available quarter and year. The script processes the raw Freddie Mac files, creates quarter-level files, combines all available quarters, and saves final modeling files.

Conclusion

The Freddie Mac origination and monthly performance files were cleaned and standardized into a loan-level dataset suitable for later modeling. The origination file provided borrower, loan, and property characteristics, while the performance file was used to create the outcome variable, any_90_dpd, which identifies whether a loan ever became 90 or more days delinquent. state_def_rate was also an engineered feature because location plays a part in mortgage risk; property values, economic stability, unemployment patterns and affordability all vary. State default rate is a good factor to include because it provides context. To avoid leakage the state default rates were calculated using only the training data.The automated Python script applies the same cleaning rules across the available Freddie Mac quarters first then merges, and completes the stratified split, calculates the rates on the training set and saves the files.HARP-related fields were removed because those loans represent a special refinancing program, while high-cardinality or low-value fields such as zipcode, seller, servicer, and selected low-variation indicators were excluded from the standardized feature set. Date fields were converted into year and month features before the original raw date columns were dropped. Missing numeric values were imputed with the median, and categorical variables were one-hot encoded so they could be used in later models.
