Modeling Strategy

This is a binary classification problem. The modeling strategy compares an interpretable baseline model (logistic regression) with more flexible classifier models.

The models used are:

  1. Logistic Regression
  2. Random Forest Classifier
  3. Histogram Gradient Boosting Classifier

Logistic regression is used as the baseline because it is interpretable and produces probabilities naturally. Random Forest and Histogram Gradient Boosting are included because they can capture nonlinear relationships and interactions among borrower, loan, and property characteristics. mi_cancel was dropped post script due to an error.

x_train= x_train.drop(columns=["mi_cancel"], errors="ignore")
x_test= x_test.drop(columns=["mi_cancel"], errors="ignore")

Threshold-Based Evaluation

For a risk-advisory application, the default classification threshold of 0.50 may not be ideal. We’ll check lower thresholds as they might increase recall for risky loans, but it may also increase false positives. Its worth evaluating.

threshold_results= []

for threshold in [0.05, 0.10, 0.20, 0.30, 0.50]:
  preds= (hgb_prob >= threshold).astype(int)
  threshold_results.append({
    "threshold": threshold,
    "precision": precision_score(y_test, preds, zero_division=0),
    "recall": recall_score(y_test, preds, zero_division=0),
    "f1": f1_score(y_test, preds, zero_division=0),
    "accuracy": accuracy_score(y_test, preds)
  })

Risk Tier Function

For the prototype app, the predicted probability is converted into a simple risk label. These thresholds are prototype rules and should be refined later using calibration, business context, and user-centered design.

def assign_risk_tier(probability):
  if probability < 0.2:
    return "Low"
  elif probability > 0.2 < 0.5:
    return "Moderate"
  elif probability > 0.5 < 1.5:
    return "Elevated"
  else:
    return "High"

Final Model Choice

Our final model should be selected using a combination of predictive performance and practical use. Its justified to default to Logistic Regresion but Histogram Gradient Boosting may provide a slightly stronger performance, while Logistic Regression is easier to interpret. Because this project is intended to support a consumer-facing advisory tool, model outputs should be communicated carefully and should not imply certainty. A reasonable final approach is to use the best-performing model for probability estimation while keeping Logistic Regression as the interpretable baseline for explaining which loan characteristics are associated with higher or lower delinquency risk.

Limitations

The dataset is based on Freddie Mac historical mortgage data and may not represent all loan types or borrower populations. The target variable identifies whether a loan ever became 90+ days past due during the observed performance period, but future delinquency risk may shift under different economic conditions. The automated script will help prep all new Freddie Mac Data Releases for retraining the models.

The models are trained on US data only. The data also does not represent mortgages that don’t qualify under its standards, which may an income limit and property specifications. Freddie Mac also keeps veteran loans separate, so by extension our app excludes the veteran population

Conclusion

Our project demonstrates that Freddie Mac origination and performance data can be transformed into a model-ready dataset for predicting serious mortgage delinquency. The custom pipeline creates a larger and more defensible dataset than the initial MVP sample, while the modeling workflow shows how predicted probabilities can be turned into consumer-friendly risk tiers. The final Home Loan Advisor workflow combines data engineering, classification modeling, evaluation, and app-ready risk interpretation.
